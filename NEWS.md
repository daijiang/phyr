# phyr 1.3.0

* **Breaking change**: the restricted log-likelihood of gaussian models fitted with `REML = TRUE` and `bayes = FALSE` (`logLik`, and so `AIC` and `BIC`) no longer includes `log|X'X| / 2`. It is now the restricted log-likelihood of `lme4::lmer()`, `glmmTMB()` and `nlme::lme()` (the likelihood integrated over the fixed effects), as for `method = "Laplace"`, so that it can be compared with these packages. The estimates, and likelihood ratio tests between models with the same fixed effects (e.g. `pglmm_profile_LRT()`), do not change. The same for `cor_phylo()` with `REML = TRUE`, whose restricted log-likelihood no longer includes `log(p (n - 1)) / 2` (half the log of the sum of squares of the standardized variates, as in `ape::corphylo()`).
* **Breaking change**: the default of `sparse` in `pglmm()` and `pglmm_compare()` is now `NULL`, which uses the sparse code (`sparse = TRUE`) whenever it supports the model: random terms in the formula, phylogenies in `cov_ranef`, and, with `bayes = TRUE`, `ML.init = FALSE` and `repulsion = FALSE`; the dense code is used otherwise (it was `sparse = FALSE`). With `bayes = TRUE`, `ranef()`, `predict()` with `newdata` and `simulate()` with `re.form = NA` need `sparse = FALSE` for now. Both fit the same model, the sparse code being faster from about 1000 observations (and much faster for large phylogenies); the estimates can differ slightly, as the optimizers differ (for binomial and poisson models fitted by PQL, the log-likelihood also depends on the path of the iterations, e.g. by 0.003 in our examples). Use `sparse = FALSE` for the previous behavior; `vcv.phy` of `pglmm_compare()` is only returned by the dense code.
* **Breaking change**: binomial and poisson models with `bayes = FALSE` are now fitted with the Laplace approximation (`method = "Laplace"`) by default, instead of penalized quasi-likelihood (PQL), which underestimates the variances of random terms (and shrinks the fixed effects) for binary data and small counts. Their estimates thus change, and their log-likelihood (and `AIC`, `pglmm_profile_LRT()`) is now that of the Laplace approximation, the same as `glmer()` and `glmmTMB()`. Use `method = "PQL"` for the previous fits; models with `random.effects` (which the Laplace code does not support) are still fitted with PQL by default.
* `ranef()` now returns the estimates of each level of each random term (e.g. one value per species for `(1 | sp)`), as `lme4::ranef()` does, for models fitted by maximum likelihood (conditional modes, optionally with their conditional standard deviations via `condVar = TRUE`) and by INLA (posterior summaries).
* **Breaking change**: the table of variances and standard deviations of random terms that `ranef()` used to return is now returned by the new `VarCorr()` method. Replace `ranef(fit)` with `VarCorr(fit)` in existing code that uses this table.
* `predict()` now supports `newdata`, with or without random effects (`re.form`), for models with `bayes = FALSE` or `TRUE`. Levels of grouping variables that were not in the data used to fit the model need `allow.new.levels = TRUE`, and have their random effects set to zero.
* `pglmm()` with `bayes = FALSE` is much faster for large data sets, with the same results: quantities that do not depend on the parameters are now calculated once instead of at every evaluation of the likelihood (models without nested terms; the observation-level term `1|obs` of poisson and binomial models is no longer treated as a dense nested term), the block structure of nested terms is also used when there are non-nested terms, and the design matrix of random terms is built as a sparse matrix.
* On a Mac where R uses the reference BLAS library, `pglmm()` now shows a message (once per session, for models with at least 1000 observations) with the command to switch R to Apple's Accelerate, which can make large models several times faster. Nothing is changed on the computer; turn the message off with `options(phyr.blas.hint = FALSE)`.
* **Breaking change**: the fitted model no longer includes `iV` (the n by n inverse of the covariance matrix), which needed a lot of memory and time for large data sets; no function of the package needs it anymore. Use the new function `pglmm_iV()` to calculate it from a fitted model.
* Fixed bugs that gave wrong results silently:
    + a covariance matrix (not a phylogeny) in `cov_ranef` that had the same names as the levels of the data, but in a different order, was not reordered; the model was then fitted with the wrong covariance matrix.
    + with `cpp = TRUE`, models with nested terms that are not block-diagonal (e.g. `(1 | sp__@site) + (1 | sp@site__)`, or nested terms only with unbalanced data sorted by site) could be fitted as if they were, with results that depended on the order of the terms in the formula or of the rows of the data.
    + `offset()` in the formula was ignored when `bayes = FALSE`; it now gives an error.
    + `cor_phylo()`: measurement errors were assigned to the wrong species when the rows of the data were not in the same order as the tips of the phylogeny.
    + `psv()` and `psr()` with `cpp = FALSE` gave wrong results for abundances that are not larger than one (e.g. relative abundances).
* `pcd()` and `match_comm_tree()` now work with a community matrix (not only a data frame).
* Fixed predicted values of gaussian models (`bayes = FALSE`), which also changes `fitted()`, `residuals()`, `predict()` and `simulate()` of these models:
    + `gaussian.pred = "nearest_node"` (default) now gives the fitted values conditional on the estimated random effects (Xb + Zu), the same as `lme4`. It used an approximation that was not correct for models with crossed or phylogenetic random terms.
    + `gaussian.pred = "tip_rm"` now includes the fixed effects (Xb); it used to return only the leave-one-out prediction of the residuals.
* `pglmm_predicted_values()` and `predict()` of models with `bayes = TRUE` now follow `type` (the default is the scale of the linear predictor, as documented and as for models with `bayes = FALSE`; they used to be always on the scale of the response) and `re.form`.
* `residuals()`: `scaled = TRUE` now works for gaussian models; binomial models with more than one trial now use the proportion of successes.
* `simulate()` with `re.form = NA` or `~0` now works for models with `bayes = FALSE` (it failed before); models with `bayes = TRUE` and binomial data with more than one trial are now simulated with the number of trials (it used one trial).
* Nested random terms without a covariance matrix, e.g. `(1 | sp@site)`, no longer fail when `cov_ranef` is not specified.
* `pglmm_compare(bayes = TRUE)` now returns the INLA model (`inla.model`).
* New argument `sparse` of `pglmm()` (default `FALSE`). With `sparse = TRUE`, models with `bayes = FALSE` are fitted with the sparse precision matrix of the phylogeny (including its internal nodes) and a sparse Cholesky decomposition, instead of the dense covariance matrix. This works for gaussian, binomial and poisson models; binomial and poisson models use the same penalized quasi-likelihood (PQL) iterations as `sparse = FALSE`, with the working weights changing only the values of the sparse matrix and the observation-level term `1|obs` folded into the weights. The likelihood is the same, but time and memory grow about linearly with the number of species, so models with tens of thousands of species can be fitted. It works with nested terms (e.g. `(1 | sp__@site)`) and `repulsion = TRUE`, and needs phylogenies (class `phylo`) in `cov_ranef`; transformed trees (e.g. OU with a fixed alpha, Pagel's lambda) can be used. The default optimizer is then `"subplex"`. `pglmm_iV()` (not needed by any function), predictions with `tip_rm`, and the plotting functions that need the covariance matrices are not available yet for these models. Large models with phylogenies fitted with `sparse = FALSE` show a one-time message suggesting `sparse = TRUE` (turn it off with `options(phyr.sparse.hint = FALSE)`).
* `sparse = TRUE` now also works with `bayes = TRUE`, with the new argument `sparse_method` of `pglmm()` choosing how the phylogenetic terms are given to INLA. `"precision"` (default) is a latent field over all nodes of the phylogeny with the sparse precision matrix of `sparse = TRUE`, which gives the posterior of the internal nodes (ancestral states) too. `"flow"` is the phylogenetic flow representation of the phyf and fibre packages: independent rates of evolution on the branches, mapped to the tips by the sparse matrix of the branch lengths from the root to each tip, with the variance of each rate proportional to one over the length of its branch. This is the same Brownian motion model, and gives the posterior of the rate of each branch, on the scale of the trait per unit of branch length. Nested terms with one or two phylogenies (e.g. `(1 | sp__@site)`, `(1 | sp__@site__)`) use the row-wise Kronecker product of the flow matrices (rates of pairs of branches). Both methods give the same estimates as `sparse = FALSE` and report the marginal log-likelihood of the model (with `"flow"`, up to about one unit); the estimates of rates or nodes are in `bayes_sparse$latent` of the fitted model. `repulsion`, `ML.init`, `ranef()`, `predict()` with `newdata` and `simulate()` with `re.form = NA` (any `simulate()` for `"flow"`) are not available yet for these models.
* With `sparse = TRUE` (and `method = "Laplace"`), phylogenies with internal branches of length zero are now collapsed to polytomies as documented; they used to stop with an error about terminal branches of length zero.
* The log-likelihood of models fitted with `bayes = TRUE` (`logLik`) is now the marginal log-likelihood of the model: INLA leaves out half the log determinant of the precision matrix of each random term (`Cmatrix` of its `generic0` model), which is now added back. This changed the value for nested terms (whose matrices do not have a determinant of one), for `standardize_cov = FALSE`, for covariance matrices given in `random.effects`, and with `bayes_options = list(diagonal = ...)`; DIC, WAIC and the estimates are unchanged.
* New argument `method` of `pglmm()` and `pglmm_compare()` for binomial and poisson models with `bayes = FALSE`: `"Laplace"` (the default), the Laplace approximation of the marginal likelihood, as in `lme4::glmer()` (`nAGQ = 1`) and `glmmTMB`, or `"PQL"` (penalized quasi-likelihood, as before). PQL underestimates the variances of random terms (and shrinks the fixed effects) for binary data and small counts; with `method = "Laplace"`, the estimates and the log-likelihood are the same as those of `glmmTMB()` with a phylogenetic covariance matrix (`propto()`) and of `glmer()` without phylogeny, so that `logLik()`, `AIC()` and `pglmm_profile_LRT()` use a proper approximation of the marginal likelihood. It uses the sparse precision matrices of `sparse = TRUE` (whatever the value of `sparse`; covariance matrices in `cov_ranef` are used through their inverse), so it is fast for large phylogenies (about 3 s for 5000 species and 25000 observations), and supports nested terms, `repulsion` and the observation-level term `1|obs`. With `REML = TRUE` (the default), the fixed effects are integrated out as in `glmmTMB(REML = TRUE)`; use `REML = FALSE` for maximum likelihood estimates. `summary()` shows which approximation was used.
* New family `"nbinomial"` of `pglmm()` and `pglmm_compare()`: the negative binomial distribution for overdispersed counts, with the log link and the variance `mu + mu^2 / theta` (as `lme4::glmer.nb()`, `glmmTMB(family = nbinom2)` and `MASS::glm.nb()`). With `bayes = FALSE`, it is fitted with the Laplace approximation (`method = "Laplace"`, the only method available for it), with the dispersion `theta` estimated with the other parameters (element `theta` of the fitted model, shown by `summary()`; `theta = Inf` is the poisson model), and gives the same estimates and log-likelihood as `glmmTMB(family = nbinom2)`. No observation-level random term is added. With `bayes = TRUE`, the families `"nbinomial"` and `"zeroinflated.nbinomial"` are fitted by INLA. `residuals()`, `fitted()`, `predict()`, `simulate()`, `ranef()` and `pglmm_profile_LRT()` support these models. MASS is now imported (for the starting values from `MASS::glm.nb()`).
* `pglmm_iV()` and `pglmm_predicted_values(gaussian.pred = "tip_rm")` now work for models fitted with `sparse = TRUE` and `method = "Laplace"` (they gave an error): they are calculated from the sparse factorization of the fit with the Woodbury identity, with the diagonal of the inverse of the covariance matrix from the selected inverse.
* `offset()` terms in the formula (e.g. `+ offset(log(effort))` for counts with different sampling efforts or areas) are now supported with `bayes = FALSE` and `method = "Laplace"` (binomial, poisson and negative binomial models), with the same estimates and log-likelihood as `glmmTMB()`; they gave an error before (they are still not supported with `method = "PQL"` and gaussian models). `predict()` (with or without `newdata`, where the offset is calculated from `newdata`), `fitted()` and `simulate()` include the offset, also for models fitted with `bayes = TRUE`, whose predictions with `newdata` or `re.form = NA` used to leave it out.
* New family `"Gamma"` (or `"gamma"`) of `pglmm()` and `pglmm_compare()` with `bayes = FALSE`: the Gamma distribution with the log link for positive continuous responses (e.g. biomass, body size), fitted with the Laplace approximation, with the shape parameter (element `shape` of the fitted model) estimated with the other parameters. It gives the same estimates and log-likelihood as `glmmTMB(family = Gamma(link = "log"))`. `residuals()`, `fitted()`, `predict()`, `simulate()`, `family()`, `ranef()` and `pglmm_profile_LRT()` support these models. The families of `method = "Laplace"` are now defined in one place (internal "family specs", similar to the family objects of `glmmTMB`), so that more families can be added with little change to the fitting code and the methods.
* Faster negative binomial and Gamma models: the dispersion parameter (`theta`, `shape`) now has an analytic gradient too, instead of finite differences, and the log density is computed without `dnbinom()` and `dgamma()` (with the terms that depend only on the response and the dispersion computed once; for negative binomial models, accurate also near the poisson model, where `dnbinom()` approximates it).
* `method = "Laplace"`: the variances of random terms are now optimized multiplied by their `scale_factors` (the variances of an average level), with default starting values of 0.25 on this scale. With large phylogenies, the variance of a phylogenetic term on the scale of the covariance matrix standardized to a determinant of one is very small, which could make `nlminb()` stop before the optimum ("false convergence") when it is close to zero.
* Faster fits with `sparse = TRUE` and `method = "Laplace"`, with the same estimates: the variances are now estimated with `nlminb()` and analytic gradients of the likelihood (gaussian models, the PQL iterations of binomial and poisson models, and the Laplace approximation), instead of a derivative-free optimizer (`sparse = TRUE`) or finite differences (`method = "Laplace"`). The gradients use the selected inverse of the sparse Cholesky factorization (new C++ code), which also makes `ranef(condVar = TRUE)` of these models much faster for large data. The optimization is also started from the "corners" where a phylogenetic term (e.g. `1|sp__`) or its non-phylogenetic partner (`1|sp`) has all their variance, as the likelihood can have a local optimum in between. The derivative-free optimizers of earlier versions are still available with `sparse = TRUE` and `optimizer = "subplex"` (or `"nelder-mead-nlopt"`, `"bobyqa"`); the default `reltol` with `sparse = TRUE` is now `1e-10` (still `1e-8` for these optimizers). The sparse Cholesky factorizations are now always simplicial.
* `simulate(re.form = NA)` now works for models fitted with `sparse = TRUE` (except with `repulsion`).
* `repulsion = TRUE` (a single value) now inverts only the phylogenies of species in nested terms (e.g. `sp` in `(1 | sp__@site__)`), not those of sites, as in Ives and Helmus (2011, Appendix A), where repulsion comes from competition among related species. Before, it also inverted the phylogeny of sites in `(1 | sp@site__)` and `(1 | sp__@site__)`; to get that, give one value for each phylogeny, e.g. `repulsion = c(TRUE, TRUE)` for `(1 | sp__@site__)`.
* With `bayes = TRUE` and `bayes_nested_matrix_as_list = TRUE`, `repulsion = TRUE` was ignored (the covariance matrix was not inverted); fixed.
* New argument `standardize_cov` of `pglmm()` and `prep_dat_pglmm()` (default `TRUE`, the previous behaviour). With `standardize_cov = FALSE`, the covariance matrices of `cov_ranef` are not standardized to have a determinant of one but used as given (a phylogeny gives `ape::vcv(tree)`), so the variances of random terms are on the scale of these matrices. It also works with `sparse = TRUE`.
* `pglmm()` returns `scale_factors`, the mean diagonal of each standardized covariance matrix. The documentation of `pglmm()`, `VarCorr()` and `summary()` now explains how to extract the variances of random terms: use `s2r`, `s2n` and `s2resid` (not `ss^2`, which for gaussian models are standard deviations relative to the residual standard deviation), and multiply the variances of terms with a covariance matrix by `scale_factors` before comparing them with other terms or with other software, because those matrices are standardized to have a determinant of one. The example of `VarCorr()` that calculated the proportion of phylogenetic variance without this rescaling is corrected.
* `pglmm_compare()` is now built on the formula interface of `pglmm()`: it fits `(1 | sp__)` with a column of species made from the row names of the data, but without the non-phylogenetic term `(1 | sp)` that `pglmm()` adds (confounded with the residual variance when there is one row per species). The estimates are the same as before. It gains the features of `pglmm()`:
    + new arguments `sparse` (default `FALSE`; with `TRUE`, the sparse precision matrix of the phylogeny is used, for large phylogenies), `standardize_cov` (default `TRUE`, the previous standardization), `calc.WAIC`, `bayes_options`, `posterior.sample` and `return.fitted.marginals`, passed to `pglmm()`.
    + the fitted model now also has class `communityPGLMM` (`c("pglmm_compare", "communityPGLMM", "pglmm")`) and all the elements returned by `pglmm()`, so `fixef()`, `ranef()` (one estimate per species), `VarCorr()`, `fitted()`, `residuals()`, `predict()` (with `newdata`, species given by the row names), `simulate()`, `logLik()`, `AIC()`, `pglmm_profile_LRT()` and `pglmm_iV()` work. The elements of earlier versions (`phy`, `vcv.phy`, `s2n`, ...) are kept; `vcv.phy` is `NULL` with `sparse = TRUE`.
    + the conditional likelihood ratio test of phylogenetic signal mentioned in the documentation is now returned (`LRT`, from `pglmm_profile_LRT(fit, re.number = 1)`) and printed by `summary()`.
    + the default of `calc.DIC` is now `TRUE`, as in `pglmm()` (only for `bayes = TRUE`; the estimates do not change). `add.obs.re = TRUE` (the default, as documented) now adds the observation-level term `1|obs` for poisson data and binomial data with more than one trial; before, the argument was ignored and the term was never added, so the phylogenetic variance also absorbed any overdispersion. **This changes the estimates for these models**; use `add.obs.re = FALSE` to get the previous ones. Gaussian and binary (0/1) models are unchanged. `s2.init` keeps its default of 1 (`pglmm()` uses 0.25 for binomial and poisson models, which gives slightly different estimates within the tolerance of the optimizer).
    + rows with a missing response are dropped (with their tips) instead of failing.
* `pglmm()` shows a message (once per session) suggesting `pglmm_compare()` when a phylogenetic term such as `(1 | sp__)` has one row per species; turn it off with `options(phyr.compare.hint = FALSE)`.
* New `logLik()` method for models fitted by `pglmm()` with `bayes = FALSE`, so that `AIC()` works.
* `pglmm_profile_LRT()` failed for models with nested terms only (e.g. gaussian models); fixed.
